# v0.9.9 — 서버에 계정 저장, 솔로 전투만 기기에서 진행

**로그인한 계정 정보는 Cloudflare D1이 유일한 원본입니다.** v0.9.8에서 계정 정보까지 로컬로 저장한 동작을 수정했습니다.

| 기능 | 장소 | 통신 빈도 |
|---|---|---|
| 로그인/계정 불러오기 | Firebase Authentication + Cloudflare D1 | 로그인 시·새로고침 시 1회 |
| 코인, XP, 승리 기록, 타워/몬스터 팩/스킨 소유 | Cloudflare D1 | 변경 시 서버 저장 |
| 상점 구매, 타워 장착, 스킨 상자 열기 | Cloudflare D1 | 각 작업에서 1회 요청 |
| **로그인 솔로의 웨이브·적·타워·타이머·공격** | **브라우저** | **전투 중 0회** |
| 로그인 솔로 최종 보상 | Cloudflare D1 | **종료 시 1회 요청** (오류면 재시도) |
| 비로그인 게스트 솔로·보상 | 브라우저 LocalStorage | 서버 0회 |
| PvP·협동전 | Cloudflare Worker / Durable Objects / D1 | 방 입장과 서버 동기화 |
| 관리자 패널·유저 제재·프로필 수정 | Cloudflare D1 | 관리자 작업 시 |

## 서버 비용 최적화

솔로 게임방을 Durable Objects에 생성하지 않습니다. 서버 타이머·스냅샷·스폰 처리·전투 명령·WebSocket이 없습니다. 이 때문에 300명이 동시에 로그인 솔로를 진행해도 솔로 전투 도중 Cloudflare Worker/DO 호출은 0회입니다. 300명이 전투를 완료하면 전투당 보상 정산 1회를 수행합니다. 실제 웹사이트 정적 파일 다운로드, Firebase 로그인 및 상점 구매는 별도입니다.

서버는 클라이언트가 제출한 코인 또는 XP 값을 믿지 않고, 난이도·모드·웨이브를 검사하고 게임 엔진의 보상 산식으로 계산합니다. 결과 위조 방어용 서버 전체 전투 재현은 하지 않습니다(학교 친구들끼리 사용하는 게임이라는 운영 방침에 따라 저비용 구조 우선). 같은 전투의 네트워크 재시도 시 중복 지급하지 않습니다.

## 이전 v0.9.8 로컬 계정의 진행도 복구

1. 이전 패치를 플레이했던 **같은 브라우저와 기기**에서 로그인합니다.
2. **계정 관리 → 이전 v0.9.8 기기 진행도를 서버로 이전**을 누릅니다.
3. 서버의 코인/경험치/승수와 기기 값을 비교해 높은 수치를 남기고, 타워·팩·스킨 보유 정보를 병합합니다.
4. 이전 작업은 계정당 한 번만 시행되며, 재요청해도 자산을 중복 추가하지 않습니다. 성공 후 D1 데이터를 다른 기기에서도 사용할 수 있습니다.

별도 JSON 백업은 로그인 시 1회 이전 기능으로 적용할 수 있습니다. 서버의 제재 상태 및 기존 멀티플레이 룸 정보는 덮어쓰지 않습니다. **로그인 계정은 더 이상 브라우저 LocalStorage를 원본 저장소로 사용하지 않습니다.**

## 검증

`npm test`: D1 계정 구매·착용·조회, 게스트 저장, 단일 솔로 보상, 중복 정산, 정식 보상 산식, 로컬 데이터 1회 이전, PvP 서버 검증. `node scripts/offline-browser-smoke.mjs`: 실제 Chromium에서 D1 모의 계정 로그인, 구매 후 새로고침 서버 복원, 솔로 웨이브 실행 중 서버 요청 0회, 전투 종료 시 보상 요청 1회 테스트.

Cloudflare 운영 배포와 Firebase 실계정의 복수 기기 테스트는 별도 확인이 필요합니다.
