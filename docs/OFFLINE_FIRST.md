# v0.9.8 — 로그인해도 솔로/수집은 클라이언트 전용

## 어떤 기능이 서버를 사용하는가?

| 기능 | 게임 로직/데이터 위치 | 전투/상점 중 Cloudflare 요청 |
|---|---|---|
| 비로그인 솔로 | 브라우저 | 0 |
| 로그인 솔로 | 브라우저 | **0** |
| 스토리, 웨이브 타이머, 타워 배치·강화 | 브라우저 | **0** |
| 상점, 타워/스킨/몬스터 팩 구매·장착 | 브라우저 | **0** |
| 솔로 클리어 보상 및 도감 | 브라우저 LocalStorage | **0** |
| PvP / 협동전 방 검색·참가·전투 | Cloudflare Worker, DO + Firebase 인증 | 기존 약 3초 주기 및 유저 명령 |
| 관리자 유저 조회·제재·진단 | Cloudflare Worker + D1 | 관리자 명령 시에만 |
| 로그인/회원가입 | Firebase Authentication | 로그인과 인증 처리 시 |
| 이전 클라우드 저장 가져오기 | Cloudflare D1 | 계정 메뉴에서 버튼을 **직접 누른 경우에만** |

게임 웹페이지 자체를 처음 받는 정적 파일 요청과 Firebase SDK의 로그인·인증용 네트워크는 제외한 수치입니다. 브라우저에서 솔로 게임이 진행되는 동안 **Cloudflare Worker의 방 생성, WebSocket, pulse, D1 쓰기/읽기 또는 결과 claim을 발생시키지 않습니다.** 게임 실행 중 따로 서버에 실시간으로 동기화하지도 않습니다.

### 왜 계정별로 저장을 분리하나요?

- 비로그인 진행도 키: `shinsung.profile.v1`
- 로그인 사용자 UID별 진행도 키: `shinsung.profile.account.v2.<uid>`
- 기존 기기에서 첫 로그인하면 게스트 진행도를 해당 로그인 프로필로 **복사**합니다. 이후에는 저장 영역이 완전히 분리되어 다른 계정의 코인, 타워와 섞이지 않습니다.
- 이전 버전 D1에 저장된 데이터가 필요하면 **계정 관리 → 이전 서버 진행도 한 번 가져오기 (선택)** 버튼을 누릅니다. 현재 코인/경험치/승수와 이전 값을 비교해 높은 값을 유지하고 타워·팩·스킨 보유 내역은 합칩니다. 자동 요청이 아니므로 일상적인 솔로 플레이 비용은 증가하지 않습니다.
- 기기를 바꾸거나 브라우저 저장 데이터를 지우면 해당 기기의 로컬 진행도는 복구되지 않습니다. **계정 로그인만으로 기기 간 동기화가 되지는 않습니다.** 중요한 경우 브라우저 저장 데이터를 유지해야 합니다.

### 멀티플레이는 어떻게 동작하나요?

- PvP와 협동전에서만 서버가 전투를 판정하고 방을 관리합니다.
- 로컬 장착 타워 최대 5개와 몬스터 팩, 해당 장착 타워 스킨 설정만 서버에 전송하여 현재 기기의 로드아웃을 그대로 사용할 수 있습니다. 로컬 코인/XP, 전체 보유 재고, 상자 뽑기 기록은 전송하지 않습니다.
- 로그인 사용자에 대한 온라인 이용 제한과 방 점유 상태만 D1에서 검증합니다. 관리자 제재는 서버 멀티플레이 접근에 적용됩니다. **오프라인 솔로는 서버에 연결하지 않으므로 원격 제재를 즉시 적용할 수 없습니다.**
- 멀티플레이 보상은 서버에서 정상적인 결과를 확인한 뒤 기기 프로필에도 한 번만 반영합니다.

### 성능 및 검증

- 솔로는 브라우저 자체 20Hz 결정론적 전투 엔진을 사용하여 서버 왕복 지연이 없습니다.
- 모든 상점/컬렉션 변경은 서버 요청 없이 즉시 반영됩니다.
- 300명이 동시에 **솔로 게임 중**이라도 주기적인 Cloudflare 전투 요청은 이론상 **0회**입니다. 물론 웹페이지 초기 접속이나 계정 로그인 인증은 별도입니다.
- `npm test`: 소스 내 서버 호출 금지 경로, UID별 저장 분리, 장비 최소 전송, 서버 솔로 생성 금지, 기존 전투 회귀 검사.
- `node scripts/offline-browser-smoke.mjs` (Playwright 설치 후): 가상 로그인 사용자로 외부 네트워크 요청을 모두 감시하면서 상점 구매, 계정별 로컬 저장 및 솔로 웨이브 진행을 실제 Chromium에서 검증.
