# Cloudflare 무료 플랜 게임방 절감 설계 — v0.9.6

## 원칙

서버는 타워 설치, 적 피해, 웨이브 종료, 보상과 승패를 판정한다. 브라우저는 같은 결정론적 전투 엔진으로 **표시용** 상태만 앞서 재생하고 서버 스냅샷이 도착하면 교정한다. 클라이언트의 예측 데이터를 서버 입력이나 보상으로 신뢰하지 않는다.

## 무료 한도와 계측 방법

2026-11-01 기준 Cloudflare 공식 문서:
- https://developers.cloudflare.com/workers/platform/pricing/
- https://developers.cloudflare.com/durable-objects/platform/pricing/
- https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/
- https://developers.cloudflare.com/d1/platform/pricing/

무료 Workers/DO 요청 한도 각각 하루 100,000회. DO 수신 WebSocket 메시지는 20개당 요청 1회로 계산되며 송신 WebSocket 메시지에 별도 요청 요금은 없지만 CPU·DO 실행 시간·데이터 크기를 계속 관리해야 한다.

| 대상 | 이전 v0.9.5 | v0.9.6 | 절감 |
|---|---:|---:|---:|
| 게임방 1시간 주기 수신 WebSocket 메시지 | 4,000 | 1,200 | 70% |
| 게임방 1시간 주기 서버 저장(변화 없는 웨이브 가정) | 약 450 | 약 300 | 약 33% |
| 공개 방 목록 조회 / 시간 / 탐색 중 한 사용자(방 있음) | 약 424 | 약 164 | 약 61% |
| 공개 방 목록 조회 / 시간 / 탐색 중 한 사용자(방 없음) | 약 424 | 80 | 약 81% |
| 구형 이펙트 140개를 포함한 테스트 스냅샷 | 18,230B | 2,342B | 87% |

이 수치는 **호스트 신호와 공개 목록의 설정 주기, 자동 테스트의 특정 이펙트 사례로 산출한 값**이다. 실서비스 네트워크 대역폭·월간 비용·D1 행 쓰기량의 관측치가 아니며 보증도 아니다. 명령으로 인한 즉시 저장 및 이벤트에 따른 스냅샷 수는 별도로 더해진다.

## 안전 및 동기화

1. **주기 서버 진행:** 방장의 WebSocket heartbeat는 3초마다 하나만 전송. 손님은 최근 8.5초간 갱신이 없을 때만 대행을 시도하여 중복 계산을 방지.
2. **표시 보간:** 브라우저는 20Hz 게임 엔진을 복제 상태에서 실행. 최대 4.25초까지만 예측하고 12tick/렌더 프레임으로 CPU 사용을 제한. 서버 명령 결과를 즉시 반영.
3. **저장 최적화:** 12초 기준 주기 체크포인트를 작성하고 명령·웨이브 전환·경기 종료 때 즉시 저장. DO 강제 재시작이나 연결 중 hibernation으로 구 버전 체크포인트를 다시 읽었을 때, 살아 있는 WebSocket이 있다면 15초 이내의 손실 시간을 결정론적으로 복구. 모든 사람이 떠난 오래된 방은 무한 복구하지 않고 기존처럼 일시 정지.
4. **패킷 축소:** 시각적으로 이미 만료된 0.8초 이전 이펙트 데이터는 게임방 상태에서 폐기. 네트워크에 내부 영속화 필드/멤버 UID/프로필을 포함하지 않음.
5. **저장 DB:** 기존 계정 요청은 우선 SELECT로 프로필을 읽고 계정이 없을 때만 INSERT. 변경사항은 여전히 버전 검사 CAS.
6. **로비 조회:** 공개 방 있음 22초, 없음/오류 45초 자동 새로고침. 즉시 새로고침 버튼, 방 코드 직접 입장은 유지. 백그라운드 탭에서 자동 목록 조회 중단.

## 운영 모니터링

Cloudflare Dashboard에서 Workers Requests, DO Requests/Duration/SQL rows, D1 Rows Read/Written, 런타임 오류율을 주기적으로 확인한다. 무료 할당량은 전체 계정의 사용량이므로 동시 게임방 수가 늘어나면 별도 운영 제한이 필요할 수 있다.

검증 명령: `npm test` (회귀/예측/저장/호스트 승계/페이로드), 그리고 `node scripts/browser-smoke.mjs` (Chromium 테스트 준비 후). 실제 친구들과의 2인 PvP, 4인 협동, 휴대폰 화면 갱신, 모바일 백그라운드 복귀도 배포 후 실환경 테스트해야 한다.
